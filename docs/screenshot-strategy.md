# Screenshot methodology

Capture the real application UI with a temporary data directory, synthetic fixtures and intercepted API responses. Never connect production accounts or rewrite screenshots to fabricate functionality. The script is `scripts/capture_portfolio_screenshots.py`; actual captured scenarios and page errors are recorded in `docs/assets/screenshots/capture-report.json`.

The current gallery covers Central, ticket inspection and paused T01 configuration. These are UI evidence only. API execution, browser extension interoperability, evidence uploads, batch processing and live messaging require separate verification. A sanitized proactive-review capture is planned and must be produced from the RC4 UI with synthetic fixtures.

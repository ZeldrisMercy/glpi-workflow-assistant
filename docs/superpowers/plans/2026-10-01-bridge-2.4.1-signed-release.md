# Bridge 2.4.1 Signed Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the signed Browser Bridge 2.4.1 artifact and align repository source, release metadata and documentation.

**Architecture:** Treat the signed XPI as the release artifact and the extracted non-signature files as the public source snapshot for `extension/`. Keep release metadata hash-based so users can verify downloads without trusting prose.

**Tech Stack:** Firefox WebExtension MV3, Node validation scripts, Python release contract tests.

**Spec:** User-provided signed Firefox XPI for Browser Bridge 2.4.1.

## Global Constraints

- Keep the project independent and unattributed to any private legal entity.
- Keep AGPL-3.0-or-later positioning.
- Do not claim CodeQL/security completion beyond verified repository controls and fresh local checks.
- Publish signed Firefox XPI status accurately.

## Review Focus

- Source and release artifact version mismatch: `extension/manifest.json` and reproducible `dist/*.xpi` must report 2.4.1.
- Stale release docs: README, changelog, compatibility, source map and limitations must not call the Firefox XPI unsigned.
- Hash drift: release manifest and publication report must use final SHA-256 and byte size values.
- Regression tests: bridge static and release contract tests must expect 2.4.1.
- Sanitization: no private company attribution or sensitive domain should be introduced.
